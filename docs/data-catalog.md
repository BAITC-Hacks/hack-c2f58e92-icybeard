# Каталог датасетов МЗ РК (портал Ashyq Data)

Источник: https://ashyq.data.gov.kz (Magda). Все наборы опубликованы МЗ РК 2026‑09‑06, лицензия CC BY.
Локальная папка: `DataSets/<Название набора>/<оригинальное имя файла>.csv` (кодировка UTF‑8 с BOM, разделитель запятая).
Метаданные и ссылки на части: `GET https://ashyq.data.gov.kz/api/v0/registry/records/<id>?aspect=dcat-dataset-strings&aspect=dataset-distributions&dereference=true`.
Файлы лежат на `https://magda-minio-web.data.gov.kz/magda-datasets/<slug>/<имя>_part_NNN_of_MMM.csv` (путь надо URL‑кодировать).

## Ключи для соединения

| Ключ | Где встречается | Формат |
|---|---|---|
| Код региона (КАТО, 2 знака) | направления (`hospitalization_code` сегмент 1), ожидающие (`region_origin_code`), ставки (`region_id`) | `10` Абай, `11` Акмолинская, `15` Актюбинская, `19` Алматинская, `23` Атырауская, `27` ЗКО, `31` Жамбылская, `33` Жетісу, `35` Карагандинская, `39` Костанайская, `43` Кызылординская, `47` Мангистауская, `55` Павлодарская, `59` СКО, `61` Туркестанская, `62` Ұлытау, `63` ВКО, `71` Астана, `75` Алматы, `79` Шымкент |
| Код МО (4 символа) | направления (сегмент 2 кода), ожидающие (`mo_destination_code`), медтехника (`mo_id`), вакцинация (`medicine_organization_code`) | `00MY`, `4010`, `08EP` |
| Код профиля койки | направления (сегмент 3), ожидающие (`profile_code`) | `021` терапия, `031` кардиология, `321` неврология, `381` офтальмология, `DH` дневной стационар |
| Составной код госпитализации | направления `hospitalization_code` = `регион.МО.профиль.номер`; ожидающие хранят те же 4 поля раздельно | `10.00MY.072.1` |
| Наименование МО (строка) | направления, отказы, пролеченные, ставки | нормализовать кавычки и пробелы перед матчингом |

## Как читать локально

```python
import duckdb
D = "DataSets"
con = duckdb.connect()
con.execute(f"""
CREATE VIEW referrals AS
SELECT *,
       split_part(hospitalization_code, '.', 1) AS region_code,
       split_part(hospitalization_code, '.', 2) AS mo_code,
       split_part(hospitalization_code, '.', 3) AS profile_code,
       date_diff('day', try_cast(registration_dt AS DATE), try_cast(hospitalization_dt AS DATE)) AS wait_days
FROM read_csv('{D}/Направления на плановую госпитализацию в стационары/*.csv',
              header=true, all_varchar=true, union_by_name=true)
""")
```

Скрипт полного профилирования: `scripts/profile_datasets.py`.

## Загрузка и проверка целостности

- Загрузчик: `python scripts/download_datasets.py vac_facts treated_list --workers 4` (список алиасов: `--list`). Один экземпляр на папку, части качаются заново без докачки и проверяются по размеру, по multipart‑ETag сервера (части по 10 МиБ, работает для вакцинации и медтехники) или по проходу через CSV‑парсер.
- **Никогда не запускать два загрузчика в одну папку одновременно**: 9 сентября два параллельных процесса испортили 64 части вакцинации (файлы больше оригинала или с перемешанным содержимым при верном размере). Испорченные части удалены и качаются заново.
- Проверено 9 сентября: направления, ожидающие, отказы приёмного покоя, пролеченные по МО, онкология, ставки, медтехника, отказы от вакцинации совпадают с сервером по размеру и проходят строгий разбор CSV с единственным заголовком.
- Ловушка парсера: у «Отказов от вакцинации» автоопределение диалекта в DuckDB теряет 16 тыс. строк. Читать с явными параметрами `quote='"', escape='"'`, тогда все 66 709 строк на месте. Для остальных наборов лучше тоже задавать кавычки явно.
