# План реализации Darumen Health для GovTech Camp

Детальный план на четыре недели для команды из четырёх‑пяти человек; стек по [tech-stack.md](tech-stack.md). Если состав или срок другие, меняются номера дней, а не порядок задач. Каждая задача имеет владельца по роли, вход, выход и условие готовности. Правило всего плана: **поток, модель или экран без метрики на отложенной выборке в демо не попадает.**

Схемы витрин: [gold-schemas.md](gold-schemas.md). Внешний REST: [api.md](api.md). Контракты gRPC и событий: `proto/`.

Роли: **ML** (модели и оценка, Python), **Data** (intake, gold, Python), **Backend** (.NET, Kafka, Postgres, ClickHouse), **Web** (Vue), **Mobile** (Flutter, скрайб), **Lead** (документы, организаторы, защита; совмещается с одной из ролей).

## Вехи

| Веха | День | Что должно работать |

| M4 Готовность к защите | 20 | Чистый клон поднимается одной командой, README, видео, презентация, две репетиции |

### T0.11: подход к Wolverine и Schema Registry

1. Wolverine с `UsePostgresqlPersistenceAndTransport` для durable outbox и inbox; `UseKafka` для транспорта; каждое сообщение из `proto/darumen/v1/events.proto` маппится на топик через `PublishMessage<T>().ToKafkaTopic("...")`.
2. Сериализация: реализовать `IMessageSerializer`, который оборачивает `Confluent.SchemaRegistry.Serdes.ProtobufSerializer<T>` и `ProtobufDeserializer<T>` (формат wire: magic byte, id схемы, индексы сообщения, тело). Регистрировать серилизатор на конечных точках Kafka; локальные очереди остаются на JSON.
3. Регистрация схем: при старте `Darumen.Api` регистрирует схемы событий под субъектами `<topic>-value` с совместимостью `BACKWARD`; Python‑потребители используют `confluent-kafka` с `ProtobufDeserializer` по тем же субъектам.
4. Dead‑letter: `<topic>.dlq` через политику ошибок Wolverine `MoveToDeadLetterQueue` после 3 попыток с экспоненциальной задержкой.
5. Идемпотентность: таблица `inbox` Wolverine по `event_id` из `EventMeta`; обработчики без побочных эффектов вне транзакции.
6. Тест: Testcontainers поднимает Postgres, Kafka и Schema Registry; тест публикует `BatchLoaded` в транзакции с записью в Postgres, откатывает вторую попытку, проверяет ровно одну доставку; второй тест читает то же сообщение Python‑скриптом из `ml/` по схеме из реестра.
7. Если за день 3 сериализатор не заводится: временно Protobuf без реестра (чистый байтовый payload с заголовком `schema-id`), реестр подключить на неделе 3. Это не меняет контракты.

- T1.2 → T1.6 и T1.8: симулятор и индекс строятся на выходах M1.
- T2.1 → все экраны; T2.2 → окно вопросов в Gov.
- Ответы организаторов: коечный фонд меняет T1.6 с пропускной способности на занятость коек; справочник аптек включает «где получить» в T1.7 и T3.2.

## Линии отсечения

Если к дню 10 нет M1: останавливаем всё, кроме M1 и Gov. Если к дню 15 нет API: режим врача остаётся в вебе, Flutter только гражданин. Если к дню 17 скрайб не проходит сценарий: уходит в слайд «дальше». Lab, Family и онкология всегда остаются потоками с метрикой без собственных экранов, если не хватает времени.
