# План доработки кода Darumen Health

Составлен 17 сентября 2026 по итогам полного чтения репозитория (код .NET, Python, Vue, Flutter, тесты, CI, Docker, документы). Задача: довести весь функционал до рабочего и законченного состояния, не ломая то, что уже работает. План касается только кода. Деплой, видео, репетиции и презентация остаются за командой.

Размер задач: **S**: до 2 часов, **M**: полдня, **L**: 1–2 дня.

## 0. Правила работы

1. **Сначала базовая линия, потом правки.** До первого изменения снимаем текущее состояние: `make test`, `npm run walk` (скриншоты в `apps/web/e2e/shots`), `make eval` (отчёт `lakehouse/models/report.json`), дамп схемы `journal` из Postgres. Это эталон для сравнения.
2. **Одна задача = одна ветка.** Ветки `fix/<тема>` и `feat/<тема>` от `main`. В `main` сливаем только после зелёных тестов и прогона `walk`.
3. **Только добавляющие изменения в контрактах.**
   - В `proto/` новые поля получают новые номера, старые не удаляются и не переименовываются.
   - В REST новые поля DTO необязательные, существующие не меняют смысл.
   - Новые миграции EF создаются отдельно, существующие (`Initial`, `Intake`, `Audit`) не трогаем.
4. **Модели не перезаписываем вслепую.** Переобучение идёт в копию lakehouse (`lakehouse-next`). Сравниваем `make eval` с эталоном, потом переключаем. Карточки моделей генерирует `make train`, руками их не правим.
5. **На каждую исправленную ошибку пишем тест**, который падал до правки: xunit в `tests/Darumen.Tests`, pytest в `ml/tests`, vitest в `apps/web/src/__tests__`.
6. **Не трогаем без отдельного решения:**
   - раскладку lakehouse и формат манифестов;
   - существующие контракты наборов (`contracts/`) и потоки (`streams/`);
   - режимы Kafka и Keycloak, реалм `infra/keycloak`;
   - удаление ClickHouse, Cube, MinIO и Valkey из dev-стека.
7. **Документация кода** (`status.md`, `api.md`, `criteria-map.md`, `demo-pages.md`) обновляется в той же ветке, что и код.

### Как проверяю изменения

Командная строка компьютера разработчика сейчас недоступна (обновление Windows от 8 сентября ломает доступ к папке). Поэтому проверка делится на две части:

- **В облачном рабочем месте Claude:** `dotnet test` (тесты используют заглушки), `pytest ml/tests` (на синтетических данных), `vitest` и `vue-tsc` для веба. Для веба нужен `apps/web/package-lock.json`, для .NET — SDK 10.
- **На машине разработчика:** всё, что требует реальных данных и живого стека: `make data/gold/train/eval/publish`, `make up`, `npm run walk`, `flutter test`.

## Что не делаем в коде

- **Нет данных.** Координаты организаций и аптек, названия МНН, полигоны регионов, лабораторные данные ЕИП. Если данные появятся, задачи ложатся на уже готовые места: `mo_registry.lat/lon`, `pharmacies` в ответе рецепта, `RegionMap.vue`, поток `lab_weekly`.
- **Вне кода.** Деплой, видео, репетиции и презентация — за командой.
